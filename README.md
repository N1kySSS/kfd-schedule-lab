# Лабораторная «Ничего не падает»: расписание

Консольное приложение на Kotlin. Читает файл с расписанием, хранит корректные занятия и сообщает об ошибках во входных данных. Модель занятий проверяет себя при создании, поэтому её нельзя испортить через публичный API.

## 1. Как собрать и запустить

Нужны JDK 25 (путь к нему указан в `JAVA_HOME`) и Python 3.10+ для проверки.

Windows PowerShell, из корня проекта:

```
.\gradlew.bat build :app:installDist
.\app\build\install\schedule\bin\schedule.bat period --file samples/clean.txt --from 2026-09-28 --to 2027-05-13
.\app\build\install\schedule\bin\schedule.bat type --file samples/dirty.txt --type EXAM
.\app\build\install\schedule\bin\schedule.bat errors --file samples/dirty.txt
```

Linux/macOS:

```
./gradlew build :app:installDist
./app/build/install/schedule/bin/schedule period --file samples/clean.txt --from 2026-09-28 --to 2027-05-13
./app/build/install/schedule/bin/schedule type --file samples/dirty.txt --type EXAM
./app/build/install/schedule/bin/schedule errors --file samples/dirty.txt
```

Тесты:

```
.\gradlew.bat test
```

Проверка вывода на эталонах (после `installDist`):

```
python tools/verify.py
```

Коды завершения: 0 если файл обработан и отклонённых строк нет, 1 если отклонённые строки есть, 2 если неверные аргументы или файл не прочитан.

## 2. Почему обычный class, а не data class

Я выбрал обычные `class` для `Lecture`, `Practice`, `Exam` и `Cancelled`.

Причина в списке преподавателей. Мне нужно хранить не тот список, который передали в конструктор, а его копию. У `data class` каждый параметр первичного конструктора сразу становится полем, и в поле попадает ровно то, что передали. Получилось бы, что чужой изменяемый список лежит внутри занятия.

Ещё у `data class` есть автоматический `copy()`, который работает через свойства конструктора и мог бы подставить в объект чужой список. У обычного класса `copy()` нет, поэтому обойти проверки этим способом нельзя. Минус обычного класса: `equals`, `hashCode` и `toString` я написал вручную.

У `Cancelled` нет полей места и преподавателей, даже nullable, как требует задание.

## 3. Защита коллекций

Есть два случая.

**Случай 1: меняют исходный список после создания занятия.** В конструкторе я сохраняю копию списка в закрытое поле:

```kotlin
private val savedTeachers: List<String> = teachers.toList()
```

Проверки в `init` идут по этой копии. Поэтому `names.clear()` снаружи не влияет на занятие.

**Случай 2: меняют список, полученный от занятия.** Публичное свойство каждый раз отдаёт новую копию:

```kotlin
val teachers: List<String> get() = savedTeachers.toList()
```

Что бы ни сделали с полученным списком, внутренний список занятия не меняется.

Реестр защищён так же: `all()` возвращает `items.toList()`, то есть снимок на момент вызова. Если потом изменить реестр, снимок не изменится, и если изменить снимок, реестр не изменится. Журнал в `AuditedSessionRepository` (свойство `events`) тоже отдаётся копией.

## 4. Делегирование: почему недостаточно переопределить только add

`AuditedSessionRepository` объявлен как `SessionRepository by delegate`. Это значит, что Kotlin сам передаёт все методы интерфейса во внутренний реестр `delegate`, который реально хранит занятия.

Если переопределить только `add`, пакетное добавление в журнал не попадёт. Когда вызывают `addAll` у обёртки, вызов просто уходит во внутренний реестр. Тот добавляет занятия сам и не обращается к методу `add` обёртки, потому что вообще не знает, что она существует.

Событие в журнал пишется только после того, как делегат успешно отработал. Метод `all()` не переопределён, поэтому он не создаёт событий.

## 5. «Сломай свою модель»: что защищает в каждом случае

| Попытка | Результат | Что защищает |
|---|---|---|
| Создать занятие с пустой темой (или из пробелов) | `IllegalArgumentException` | проверка при создании (`init`) |
| Создать занятие с годом 0 или 10000 | `IllegalArgumentException` | проверка при создании (`init`) |
| Создать лекцию или практикум без преподавателей | `IllegalArgumentException` | проверка при создании (`init`) |
| Создать сдачу с одним преподавателем | `IllegalArgumentException` | проверка при создании (`init`, минимум 2) |
| Создать сдачу с двумя одинаковыми преподавателями | `IllegalArgumentException` | проверка при создании (`init`) |
| Изменить исходный список после создания занятия | занятие не изменилось | защита коллекции (копия при создании) |
| Изменить состояние занятия через выданный список | занятие не изменилось | защита коллекции (каждый раз отдаётся новая копия) |
| Обойти проверки через `copy` | сделать нельзя | устройство типа (`copy()` у обычного класса нет) |
| Получить у отмены место или преподавателей | сделать нельзя | устройство типа (у `Cancelled` нет таких свойств) |

## 6. Сообщения об ошибках, которые я придумал сам

Обязательные сообщения из задания реализованы как есть, а для остальных причин я выбрал следующие сообщения:

| Причина | Сообщение |
|---|---|
| Управляющий символ | `line N: field "topic" contains a control character in "..."` |
| Пробел в начале или в конце | `line N: field "topic" has leading or trailing whitespace in "..."` |
| У отмены место или преподаватели не `-` | `line N: cancelled session requires "-" in field "location", got "..."` |
| Недопустимое место (`-`) | `line N: invalid location "-"` |
| Недопустимый элемент списка преподавателей (пустой, пробельный или `-`) | `line N: invalid teacher name "..."` |
| Повторное имя преподавателя | `line N: duplicate teacher "Ivanov"` |

## 7. Собственные проверки

Тесты лежат в `app/src/test/kotlin/schedule`.

**Модель (`SessionModelTest`).** Корректное создание всех четырёх типов, сохранение порядка преподавателей, разный регистр имён (`Ivanov` и `ivanov` разные). Попытки сломать модель: пустая тема, год 0 и 10000, действующее занятие без преподавателей, сдача с одним преподавателем, сдача с двумя одинаковыми, изменение исходного списка, изменение списка, полученного от занятия.

**Реестр (`RepositoryTest`).** Снимок не меняется после добавления занятий, изменение снимка не меняет реестр, `addAll` сохраняет порядок, одинаковые занятия хранятся отдельно, журнал для одиночного и пакетного добавления, пустой `addAll` даёт событие с количеством 0, `all` событий не создаёт.

**Разбор строки (`ParserTest`).** По одному тесту на каждый пункт приоритета проверок (1–7) и подпункты пункта 7. Отдельно: конечное пустое поле, примеры «несколько дефектов сразу» из задания (`2026-13-45|SEMINAR|Topic|Room 1|Ivanov` даёт ошибку даты, `2026-10-05|EXAM|Topic|Room 1|Ivanov,Ivanov` даёт ошибку повторного имени) и случай, когда управляющий символ в более позднем поле важнее пробела в более раннем.

**Сообщения (`FormatterTest`).** Все шесть обязательных сообщений и экранирование (`\`, `"`, перевод строки, кириллица). Ожидаемые тексты записаны вручную.
